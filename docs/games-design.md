                                                                ↓
                                                              HTML 도구 완성 + 발표

# 🎴 게임 ④ — 고객 발견 인터뷰 (Customer Finder)

> **한 줄 정의**: "내 업무는 사실 누군가에게 결과를 넘기는 일이다. 그 '누군가'를 카드로 찾는다."

## 1. 운영 정보

| 항목 | 내용 |
|---|---|
| 회차 | 2회차 1교시 후반 (Draw Toast 직후) |
| 소요 | 20분 |
| 인원 | 개인전 (10명 동시) |
| 산출물 | "[고객]은 [고통] 때문에 힘들다. 내 도구는 [기쁨]을 줄 수 있다." 1문장 |

## 2. 학습 목표 (교육 운영 계획과의 매핑)

| 운영 계획 항목 | 게임이 채우는 부분 |
|---|---|
| 본인 업무 프로세스 흐름도 작성 | "**왜** 이 흐름이 필요한가" = 고객 관점 |
| micro-tool-interviewer | 인터뷰 전에 **타깃 사용자** 명확화 |
| 도구 컨셉 확정 | 도구의 한 줄 비전 = "X를 위한 Y" |

## 3. 카드 풀 (30장)

### Who (10) — 내 업무 결과물을 받는 사람

```
🧾 회계팀 · 📊 상사·임원 · 📦 현장 담당 · 👤 임직원 (휴가·복지)
🏢 외주사 · 🏛 감사실 · 💰 결재권자 · 🔧 시설팀
📞 민원인 · 🤖 다른 시스템 (전산 연계)
```

### Pain (10) — 그 사람의 진짜 불편

```
⏰ 응답이 너무 늦다  · ❓ 어디까지 진행됐는지 모른다
🔁 같은 걸 또 물어본다  · 📑 양식이 매번 다르다
🚫 반려 사유가 불명  · 🌀 어떻게 시작할지 모른다
🗓 시즌마다 폭증한다  · 💢 표 형식이 깨져 있다
🔍 데이터를 일일이 옮긴다  · 📎 첨부가 누락된다
```

### Gain (10) — 해결됐을 때 그 사람이 느낄 것

```
😊 5분 안에 끝남  · ✅ 한 번에 통과
🔔 자동 알림  · 📋 양식이 늘 똑같음
🎯 핵심만 한눈에  · 🪟 진행 상황 투명
🤝 두 번 묻지 않아도 됨  · 📈 월말 야근이 줄음
💡 신규자도 쓸 수 있음  · 🏅 상사가 칭찬함
```

## 4. 진행 시나리오 (20분)

| 단계 | 시간 | 내용 |
|---|---|---|
| ① 안내 | 2분 | "지난 게임에서 '내 머릿속'을 그렸다면, 이번엔 '내 일의 고객'을 찾아봅니다." |
| ② Who 1장 픽 | 3분 | 1회차 업무 맥락 정의서 참조 → 결과물 받는 사람 1명 |
| ③ Pain 3장 픽 | 4분 | 그 사람이 겪는 불편 3개 |
| ④ Gain 3장 픽 | 4분 | 도구가 줄 좋은 변화 3개 |
| ⑤ 문장 검토 | 3분 | 자동 생성된 한 문장 다듬기 |
| ⑥ 짝꿍 발표 | 4분 | "그 고객이 진짜 가장 힘든 게 X 맞아요?" 한 가지 되묻기 |

## 5. 강사 멘트

- 시작: *"내 일을 '내가 처리하는 일'로만 보면 도구가 안 만들어집니다. **누군가의 문제를 푸는 일**로 보면 '뭘 자동화할지'가 보입니다."*
- 끝: *"여기서 나온 한 문장이 다음 시간 흐름도의 출발점이고, 3회차 HTML 도구의 존재 이유입니다."*

## 6. 결과 산출물 형식

```markdown
## 내 업무 도구의 한 줄 비전

**누구를 위한 도구?** 회계팀

**그 사람이 지금 겪는 일?**
- ⏰ 응답이 너무 늦다
- 📑 양식이 매번 다르다
- 🔍 데이터를 일일이 옮긴다

**내 도구가 만들 변화?**
- 😊 5분 안에 끝남
- 📋 양식이 늘 똑같음
- 🤝 두 번 묻지 않아도 됨

> "**회계팀**은 응답이 늦고·양식이 매번 다르고·데이터를 일일이 옮기는 일 때문에 힘들다.
>  내 도구는 5분 안에 끝나고·양식이 늘 똑같고·두 번 묻지 않아도 되는 변화를 줄 수 있다."
```

# 🧱 게임 ⑤ — 프롬프트 레고 (Prompt Lego)

> **한 줄 정의**: "좋은 프롬프트 = 6개 블록을 잘 끼우는 것. 작문이 아니라 조립이다."

## 1. 운영 정보

| 항목 | 내용 |
|---|---|
| 회차 | 3회차 첫 20분 (바이브 코딩 본격 실습 직전) |
| 소요 | 20분 |
| 인원 | 개인전 |
| 산출물 | 본인 업무용 6블록 MD 프롬프트 + AI 결과 |

## 2. 6블록 (= 좋은 MD 프롬프트의 표준 골격)

| # | 블록 | 색 | 한 줄 | 예시 |
|---|---|---|---|---|
| 1 | 🎭 역할 | 빨강 | AI가 누구인가 | "10년차 인사팀 담당자" |
| 2 | 🌍 맥락 | 주황 | 회사·업무 배경 | "중견 엔지니어링, 매월 휴가 50건" |
| 3 | 📥 입력 | 노랑 | 받을 데이터 | "텍스트 50줄" |
| 4 | ⚙️ 지시 | 초록 | 무엇을 하라 | "의미 같은 사유 묶고 빈도순 정렬" |
| 5 | 📤 출력 형식 | 파랑 | 결과 모양 | "Markdown 표 \| 사유 \| 건수 \| %" |
| 6 | 💡 예시 | 보라 | 샘플 1~2개 | "본인질병 \| 12 \| 24%" |
| 🏅 보너스 | 금지사항 | — | 안 하길 바라는 것 | "표 외 설명 쓰지 마세요" |

## 3. 시나리오 풀 (5개, 본인 업무와 가까운 것 1개 선택)

1. 📋 휴가 사유 50건 → 분류 표
2. 🧾 출장 영수증 30장 → 정산서 초안
3. 📞 민원 50건 → 우선순위 + 응대 초안
4. 📑 회의록 5건 → 액션 아이템 추출
5. 📦 자재 입고 → 검수 체크 양식

## 4. 진행 시나리오 (20분)

| 단계 | 시간 | 내용 |
|---|---|---|
| ① 6블록 소개 | 3분 | 화면에서 6 카드 설명 |
| ② 시나리오 픽 | 1분 | 본인 업무 근접한 것 1개 |
| ③ 1차 조립 (의도적 빈약) | 5분 | 2~3블록만 → 실행 → 망함 |
| ④ 진단 | 3분 | "어떤 블록이 빠졌나" 셀프 진단 |
| ⑤ 2차 조립 (완전) | 5분 | 6블록 + 보너스 |
| ⑥ 비교 | 3분 | 옆 사람과 결과 비교 |

## 5. 채점 (6점 + 보너스 2점)

- 6블록 각 1점 (블록에 내용이 있고 키워드 매칭)
- "금지사항" 추가 시 +2

## 6. AI 실행 모드: 모의 실행 (결정됨)

- 5 시나리오 × 블록 조합 (있음/없음 64가지) 결과를 **사전 저장**
- 강사가 미리 ChatGPT로 64개 결과를 만들어 JSON에 매칭
- 학생이 "실행" 누르면 즉시 결과 표시 (네트워크·키 불필요)

## 7. 결과 인사이트

> "오늘 만든 6블록은 그대로 **HTML 코딩 프롬프트**에도 씁니다.
>  '역할 = 시니어 JS 개발자', '입력 = 내 데이터', '출력 = 단일 HTML 파일'."

# 📐 디자인 씽킹 5단계 × 게임 매핑

| 단계 | 핵심 능력 | 게임 | 산출물 |
|---|---|---|---|
| Empathize | 고객 관점 보기 | ④ 고객 발견 | 한 문장 비전 |
| Define | 진짜 문제 정의 | ④ + ① Draw Toast | 흐름도 + 문장 |
| Ideate | 후보 탐색 | (1회차 후보 3개) | 자동화 후보 |
| Prototype | 시제품 | ⑤ 프롬프트 레고 → 코딩 | MD + HTML |
| Test | 데이터 검증 | (2→3회차 과제) | 실제 데이터 시뮬 |
