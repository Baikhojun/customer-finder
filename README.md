# 🎯 Customer Finder — 내 업무의 진짜 고객 찾기

> 디자인 씽킹의 **공감(Empathize) + 정의(Define)** 단계를 카드 게임으로.
> "내 업무는 사실 누군가에게 결과를 넘기는 일이다 — 그 누군가를 찾는다."

made by **WhiteJune** · AI 활용 2차 TF 자체 교육
- **2회차 2교시 실습 ③ 직전 압축판 (10분)** — Who 1 + Pain 1 + Gain 1 — 흐름도의 "누구·왜" 확보용
- **풀버전 (20분)** — Who 1 + Pain 3 + Gain 3 + 5 Why — 디자인 씽킹 세션용

---

## 🌟 이 게임을 하는 이유

도구를 만들려면 보통 "어떻게 만들까"부터 생각합니다.
하지만 진짜로 쓸 만한 도구가 되려면 먼저 **"누구의 어떤 문제를 풀건가"**가 명확해야 합니다.

- ❌ "엑셀 양식 자동화해야지" → 누구를 위한 양식인지 모르면 결국 안 쓰임
- ✅ "**회계팀**이 매번 양식이 달라 짜증나니까, 양식 자동 생성기" → 명확

이게 디자인 씽킹의 첫 단계, **공감(Empathize)**입니다.

---

## 🎮 게임 흐름 (20분)

1. **닉네임** 입력 + 타이머 시작
2. 좌측 팔레트에서 카드 선택:
   - 👤 **Who 1장** — 내 결과물을 받는 사람
   - 💢 **Pain 3장** — 그 사람의 진짜 불편
   - 🎁 **Gain 3장** — 내 도구가 줄 좋은 변화
3. 자동 생성된 **한 문장**을 (필요하면 직접) 다듬기
4. **✅ 완성!** 누르면 갤러리에 저장 + 인사이트 표시
5. **🖼 갤러리**에서 다른 사람과 비교 / 우리 팀 분포 확인
6. **💾 PNG** 또는 **📝 MD**로 다운로드 → 다음 시간 흐름도의 출발점

---

## 🃏 카드 라이브러리 (3 카테고리 × 30장)

| 카테고리 | 카드 |
|---|---|
| 👤 **Who** (10) | 회계팀·상사·임원·현장 담당자·임직원·외주사·감사실·결재권자·시설팀·민원인·다른 시스템 |
| 💢 **Pain** (10) | 응답 늦음·진행상황 모름·또 물음·양식 매번 다름·반려 사유 불명·시작법 모름·시즌 폭증·표 깨짐·데이터 옮김·첨부 누락 |
| 🎁 **Gain** (10) | 5분에 끝·한 번에 통과·자동 알림·양식 일관·핵심 한눈·진행 투명·두 번 안 물음·야근 줄음·신규자 사용·상사 칭찬 |

> 카드에 없으면 **＋ 직접 추가** 버튼으로 본인 업무 맞춤 카드 작성 가능.

---

## 🪟 갤러리 3가지 모드

| 모드 | 용도 |
|---|---|
| **격자 보기** | 우리 팀 모든 작품을 한눈에 — "각자 누구를 보고 있나?" |
| **두 작품 비교** | 두 사람 작품을 좌우로 펼침 + 자동 인사이트 ("두 분은 다른 고객을 보고 있네요" 등) |
| **📊 우리 팀 분포** | 가장 많이 선택된 고객·불편·변화를 막대 그래프로 — **공통 고통 발견**의 시각화 |

## 📘 유신 AI 2차 TF — 2회차 2교시 압축판 (10분, 실습 ③ 직전)

> 2회차 슬라이드 33~34 사이(실습 ③ "본인 업무 흐름도" 직전)에 삽입.
> **흐름도를 그리기 전에, "내 도구는 누구를 위한 것인가" 한 문장**을 확보합니다.

### 10분 압축판 진행 시간표 (Who 1 + Pain 1 + Gain 1)

| 단계 | 시간 | 진행 |
|---|:---:|---|
| ① 접속 | 1분 | URL 접속, 닉네임 입력, **10분 타이머** |
| ② Who 1장 | 1분 | "내가 만들 도구는 **누가 쓸 도구**인가?" (회계팀·상사·임원·본인 등) |
| ③ Pain 1장 | 1분 | "그 사람이 **지금 가장 힘들어하는 한 가지**" |
| ④ Gain 1장 | 1분 | "내 도구가 줄 **가장 큰 변화 한 가지**" |
| ⑤ 한 문장 확인 | 2분 | 자동 생성된 문장 검토 — 필요하면 ✏️ 직접 수정 |
| ⑥ 완성 + 다운로드 | 2분 | ✅ 완성! → 📝 MD 다운로드 — **이 문장이 흐름도의 제목·목적**으로 이월 |
| ⑦ 다음 단계 안내 | 2분 | 강사: "이 한 문장 → 이제 mermaid.live에서 흐름도로" |

### 압축판 모드 약속

- **Pain·Gain 슬롯 3개 중 1개만 채워도 완성 OK** (시간 절약)
- 5 Why, 페르소나, 갤러리 비교 모드 **사용 안 함** (풀버전 기능)
- 흐름도 작성 시 이 게임에서 만든 **한 문장**을 mermaid 코드 첫 줄 주석 `%% 도구 목적: ...`으로 붙임

### 강사 핵심 멘트

> *"흐름도 그리기 전에, 이 한 가지만 정합시다 —*
> *내 도구는 **누가 쓸 거고, 그 사람의 어떤 불편**을 해결하나?*
> *이 한 문장 없이 흐름도부터 그리면 — 결국 안 쓰이는 도구가 됩니다."*

### 2회차 위원 결과물 ↔ Who/Pain/Gain 매칭 (실명)

| 위원 | 추정 Who | 추정 Pain | 추정 Gain |
|---|---|---|---|
| 강재구 (영수증→사업번호) | 본인(회계 전표 담당) | 사업번호 수기 매칭 반복 | 5분에 끝 |
| 금교현 (ERP↔Excel) | 본인(기획실 부장) | ERP-Excel 숫자 불일치 검수 | 한 번에 통과 |
| 김혜강 (휴가 발생량) | 본인(인사팀 1인) | 2,100명 휴먼에러 리스크 | 야근 줄음 |
| 사공훈 (한글 청구서) | 다른 부서 (데이터 입력자) | 양식 매번 다름 | 양식 일관 |
| 이승찬 (PDF 차량 추출) | 본인(자산관리) | PDF 일일이 열람 | 핵심 한눈 |
| 이태정 (인사 검수) | 인사담당 7명 | 입퇴사 정보 검증 반복 | 자동 알림 |
| 임준영 (노란색 음영 합산) | 본인(회계 부장) | 행 수 매번 다른 엑셀 수기 합산 | 5분에 끝 |
| 평주연 (SNS 콘텐츠) | 경영진·SNS 독자 | 매주 콘텐츠 아이디어 압박 | 신규자 사용 |
| 성국현 (공동도급) | 공동도급사 담당자 | 또 물음·진행상황 모름 | 자동 알림 |

## 📁 프로젝트 구조

```
customer-finder/
├── index.html              # 진입점
├── style.css               # Yooshin 폰트 + 토스트 톤
├── README.md
├── assets/
│   ├── favicon.ico
│   └── fonts/              # Yooshin Bold / Medium

    ├── cards-data.js       # Who/Pain/Gain 30장
    ├── palette.js          # 좌측 카드 팔레트
    ├── slots.js            # 1+3+3 고정 슬롯 캔버스
    ├── sentence.js         # 한 문장 자동 생성 + 인라인 편집
    ├── timer.js            # 카운트다운 타이머
    ├── stats.js            # 사이드바 통계
    ├── gallery.js          # localStorage 갤러리 + 비교 + 팀 분포
    ├── export.js           # PNG + MD 다운로드 (Yooshin 폰트 임베드)
    └── main.js             # 전체 초기화 + 도움말 + 닉네임 편집
```

순수 HTML/CSS/JS — 빌드 도구 없음. Draw Toast의 모듈 패턴을 재사용.
